# R5Flowstate 右键瞄准故障排查

## 范围与验收

独立离线客户端 `D:\R5Flowstate\Game\r5apex.exe`，本机训练服务端 `127.0.0.1:37015`。用户反馈按住右键后完全不跟随。验收必须核对实际相机和准星误差，不能只用状态文字或写入计数判断成功。

## 已观察事实

核实时间：2026-11-15，Asia/Shanghai。

- 会话 `fe9e8f6a-c758-4714-be3d-4e88616eca43` 记录了真实右键消息与 `held=1/state=8`，假人头部骨骼 12 被选中。写入计数曾达到 592；用户仍反馈画面不跟随。这些计数不能作为功能通过证据。
- 数学测试与帧时间检查没有检出失败：CTest 2/2 通过，帧时间累计约为每秒 1 秒，未观察到 dt 丢失。
- 独立一次角度对照在会话 `05cfb795-ac9f-4c83-ab8d-ac7540d4f7db` 执行：16:40:59.761 请求偏航从 0° 变成 5°；随后十帧实际引擎偏航仍为 0°，相机偏航约 -0.084°，玩家眼睛朝向也为 0°。已复现写入没有保留到后续帧。
- 当时的瞄准在 `_Host_RunFrame` 返回后直接写引擎角度缓存。现有证据将故障定位到角度生效路径；具体覆盖者需通过输入命令生成阶段继续验证。
- 当前镜像中引擎 getter 的静态首选地址为 `0x140218830`，相邻原生 setter 为 `0x140218880`。setter 的主要动作同样是规范化后写入角度缓存，未发现额外通知输入系统的调用。因此不能仅凭换成该 setter 就认定问题解决。

## 输入接口核对

通过标准用户态只读接口核对独立进程的输入对象，结果保存在 `artifacts\r5flowstate-aim\input-surface.json`。路径和 EXE 哈希在读取前核对。

当前镜像中的虚函数槽 27 包装输入命令生成，静态首选地址 `0x1407E9720`。槽 28 的 `0x1407E9780` 返回命令 +0x220 处的 64 位数值，不是命令指针，未进一步确认该扩展值的业务语义；旧版 SDK 头文件的返回类型不能直接采用。实际命令通过具体 CInput 对象的槽 9 查询，函数为 `0x1408D4CD0`，按序号取 0x228 字节跨度的条目并核对条目首个编号。这些地址是当前固定镜像的分析结果，不用于跨版本套用。运行代码采用签名定位。

原生 `SnapEyeAngles(<10,30,0>)` 对照中，客户端实际朝向为 `(9.99755859,29.9981689,0)`。输入命令的 +0x0C/+0x10 对应 `0x411FF600/0x41EFFC40`，即同一组角度；CInput 的 +0xD4/+0xD8 也保存同值。原生代码 `0x1408D3240` 起将命令角度写入 `user+0xBC`，其中 user 为 CInput+0x18，确认上一帧角度地址为 CInput+0xD4。

## 修复与使用

核实时间：2026-11-15，Asia/Shanghai。已部署 DLL SHA-256 为 `1C6ED9246ACAC56A293AF75F128EB6487C04AA688C756DA452BF8F3707F35D94`，构建日志为 `build-aim-command-phase.log`，构建退出码 0，数学回归 2/2 通过。实际客户端 PID 27656，日志会话 `17a8e435-bd5b-4301-b358-45a5b1bfd9ae`。

修复将调整从 Host 帧结束后的缓存写入移到实际输入命令生成之后，同时同步命令角度、CInput 上一帧角度和引擎角度。仍保留离线、前台、菜单关闭、实际右键按住、有效实体与真实骨骼、范围圆和可见性检查，不自动开火。原故障是旧写入路径没有同步参与后续输入与预测的角度状态；前后对照证明新路径能使真实玩家与相机转动，不能仅归结为“权限不足”。

使用方式不变：Insert 打开或关闭中文菜单，选择部位、范围与速度，关闭菜单后将目标放入中心圆，按住右键跟随，松开停止。当前保留头部、半径 180、速度 20，NPC 与其他玩家选项开启，高亮开启，方框关闭。启动脚本仍默认关闭瞄准和高亮，重启后从菜单开启。
