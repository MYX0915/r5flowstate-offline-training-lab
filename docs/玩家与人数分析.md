| 模块 RVA `0x3D3DCD0` | 32 位本地玩家实体句柄槽 | 静态指令确认，已有武器实验运行时验证 |
| 模块 RVA `0x6B515D8` | 实体条目数组起点 | 静态与已有运行时验证 |
| 条目步长 `0x20` | 每个实体条目大小 | 静态与已有运行时验证 |

令 `base` 为实际模块加载基址。读取 `h=u32(base+0x3D3DCD0)`，排除 `0xFFFFFFFF`，由 `index=h&0xFFFF` 和 `serial=h>>16` 得到条目 `base+0x6B515D8+index*0x20`。条目 `+8` 的序列号匹配后，读取条目 `+0` 的 64 位实例指针。

`0x3D3DCD0` 不是直接保存玩家指针的槽。`0x6B515D8` 是所有实体的数组，也不是玩家人数。当前绝对实例地址必须重新读取，不能复用旧会话中的值。

## 人数相关静态发现

| 项目 | 本版本位置 | 可以证明什么 |
| --- | --- | --- |
| `GetPlayerArray` | 回调函数 RVA `0x2469680` | 遍历候选实体并过滤后构建脚本数组 |
| `GetPlayerArrayIncludingSpectators` | 回调函数 RVA `0x2469B30` | 包含观战者的另一种数组构建路径 |
| `GetPlayerArray_AliveConnected` | 回调函数 RVA `0x2469C70` | 具有额外过滤条件的数组构建路径 |
| 遍历上界来源 | 全局指针槽 RVA `0x3389828` 指向对象内 `+0x34` | 循环上界；不能认定为当前实际玩家数 |
| `GetTeamPlayerCount` | 回调函数 RVA `0x229FEC0` | 按输入队伍编号查找队伍对象并读取计数 |
| 队伍指针数组槽 | RVA `0x7083068` | 保存队伍对象指针数组地址 |
| 队伍数组元素数 | RVA `0x7083080` | 该路径遍历的队伍条目数量，不是玩家人数 |
| 队伍编号 | 队伍对象内 `+0x94C`，32 位 | 与输入队伍编号比较 |
| 队伍人数 | 队伍对象内 `+0x968`，32 位 | `GetTeamPlayerCount` 返回的计数字段 |

回调函数 RVA 是代码位置，不是可以直接读整数的人数地址。队伍指针数组、队伍编号和计数字段已完成两次实时读取，并与本地玩家队伍作交叉对照；未通过队友加入、离开、死亡或观战等变化验证完整语义。

`GetTeamPlayerCount` 的等价逻辑为：取得队伍对象指针数组和元素数，按队伍对象 `+0x94C` 查找输入编号，再读取匹配对象的 `+0x968`。这不是在本地玩家对象加 `0x968`，也不是在模块基址直接加 `0x968`。

`GetPlayerArray` 从实体索引 1 开始迭代，实体条目指针每次递增 `0x20`；循环内存在空指针、虚函数转换和状态过滤。`IncludingSpectators` 与普通版本存在过滤差异，`AliveConnected` 又有附加条件。因此无法仅取循环上界或非空实体数量当作目标人数。

## 当前结论与待验证项

本地玩家入口、队伍数组结构和计数字段可以在当前会话读取。本地实体列表与队伍计数覆盖不同集合，仍没有验证一个可直接代表“当前地图所有真实玩家”的单一字段。

地图人数需要先指定统计口径：本地可见或复制到客户端的玩家实体、已连接玩家、存活玩家、包含观战者的玩家、同队玩家。这些集合不保证相同。训练假人、诱饵、武器和其他实体不应计为真人；某个对象被脚本归入 player 数组，也不自动证明它是由真人操作的账号。

进一步的动态验证应做已知加入/离开及状态变化对照，再确定哪个口径满足目标。队伍总和能否代表地图人数，也需要检查特殊队伍、观战者与重复统计，不能直接假设。
